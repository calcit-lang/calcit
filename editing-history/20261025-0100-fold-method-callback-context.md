# 内建方法复用回调类型上下文

## 问题与依据

EDN Grid 迁移发现等价的 `foldl` / `.foldl` 写法推断不同：前者能从初值和集合成员给回调提供列表类型，后者的回调中 `.concat` 被拒绝。当前 main 对应候选也能复现，并非只存在于旧维护线。

方法参数上下文已经通过实际实现身份解析用户函数，但没有处理实现本身为内建函数的情况。结果遗漏了已有 fold 回调关系，不能靠应用补充 Dynamic 或退回前缀形式掩盖。

## 修复边界

方法上下文读取已解析内建函数的现有 schema，复用已有 fold/sort 回调关系。直接调用的上下文也复用同一内建身份分派；不根据方法拼写为用户自定义方法套用语义。原参数检查、返回证明、求值次序和运行时实现不变，不增加公开入口、诊断或固定迁移规则。

## 验证

回归放在非 core 的 `test-types-inference.main/test-list-inference` 附带测试，覆盖前缀、方法、线程宏与空集合。core 命名空间允许内部动态分派，在其中单独运行会误以为类型推断已经正确，因此不能作为本问题的唯一验收。

原固定候选在非 core 回归中因缺少回调接收者 schema 失败；修复候选复用原运行器在 native、JS、WASM、WASI 四后端实际通过。现有宿主检查另验证错误成员输入和与累积值不符的返回仍被原诊断拒绝。完整检查及最终提交的结果以 PR 为准，不以本记录代替 CI 或审查。
