# 新增定长元组类型 `Tuple`

#2479 决定按 Rust 的思路给“定长、按位置异构”的 List 增加类型 `Tuple`，例如 `Tuple Number String`。运行时仍是普通 List，只在类型检查中区分；native、JS、WASM 的表示都不变。

决策（Jon，2026-10-29）：

- `Tuple` 严格定长，不支持 `& Dynamic` 尾部。
- 在静态类型为元组的位置，`nth t 0` 直接返回该位置的值，不包 `Option`；下标必须是范围内的字面量，否则报 `E_TUPLE_INDEX`。实现上把 `nth` 改写为 `&list:nth`，因为位置一定存在，`Option` 只会是 `:some`。推断层面 `nth` 在元组上也直接给出该位置的类型，使改写前后类型一致（`CALCIT_LINT_CORE=1` 的改写精度检查）。
- 异构元组不能当作任何 List 使用，包括 `List Dynamic`。同构元组（所有位置类型相同）可以当作 `List T`。

实现要点：

- `CalcitTypeAnnotation::Tuple(Vec<T>)`，参与比较、绑定、证明、替换、打印和 schema 序列化。元组之间逐位置比较，长度不同即矛盾；元组到 List 只在同构时成立；List 永远不能隐式变成元组。
- 字面量在期望类型为元组时逐位置检查（参数、返回值、带 schema 的 `def`、`assert-type`）。没有期望类型时，异构字面量仍推断为 `List Dynamic`。原本按 RFC 让它推断为元组，但在“异构元组不能给 List”的规则下，core 自身 17 个测试立即失败（例如 `update-in m ([] :a 1)`、`chunks ([] :a 1 :b 2) 2`），生态里路径和 `[] key value` 写法更多，所以先不改推断，等需要时再按上下文推断。
- `&list:nth`（`let[]` 的展开）对元组用字面量下标取位置类型，越界报 `W_TUPLE_INDEX`。
- trait 能力：所有元组满足 `Debug`、`Eq`、`Countable`、`Len`，同构元组还满足 `Mappable`。`Sliceable`、`Emptyable`、`Add` 返回接收者自身的类型，长度变了就不再是同一个元组，所以不接受。
- `first`、`get`、`map` 等按接收者特化的 core 调用把同构元组当作 `List T`；异构元组要求 List 参数，报类型不匹配。
- `decode-as` 等暂不支持元组目标。

命名：`Tuple` 以前是 Enum 的旧名。删除 core 中只会抛错的 `tuple?`、`tuple-enum` 占位，改为未知名字加删除版本提示；`W_REMOVED_DATA_API` 只保留给 `&tuple:*` 等旧 API。小写 `:tuple` 仍被当作 Enum 的旧拼写拒绝。单独的 `Tuple`（没有元素类型）在写入 schema 时报错。

新诊断编号：`E_TUPLE_INDEX` / `W_TUPLE_INDEX`。现有的 `E_UNSUPPORTED_INDEXED_RECEIVER` 表示接收者种类不支持下标访问，而这里接收者合法，问题出在下标没有被证明，需要不同的修复建议。

验证：`calcit/test-types.cirru` 的 `:tuple` 标签测试（native、JS），`type_fail_tuple_reads_and_list_operations_report_tuple_diagnostics`，Snapshot 写入校验的单元测试。`fix` 命令的迁移测试原先用 `tuple-enum` / `tuple?` 作样本，现改用仍属 `W_REMOVED_DATA_API` 的 `&tuple:enum`；“无替换、需人工判断”的删除谓词已不存在，对应测试一并删去。
