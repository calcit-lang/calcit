# 取余的跨后端语义

关联 #1557 与 #1559。#1559 的数值规格尚未定稿，本次先为 `&number:rem` 选定 issue 中列出的“限定安全整数并统一报错”方案，三后端按同一契约实现；若数值规格最终改选 f64 截断取余，只需放宽这一处定义域。

契约：两个操作数都必须是安全整数（`|x| <= 9007199254740991` 且恰好没有小数部分），除数不为 0；结果为截断取余，符号跟随被除数，不返回 `-0`。安全整数范围内的余数在 i64 中精确，因此 native 与 WASM 都转换为 i64 计算，JS 的 `%` 对有限 f64 本身精确，再加 0 去掉 `-0`。

native 不再借用 `f64_to_i32`：它用 EPSILON 容差判断整数，并对超出 i32 的值饱和截断，导致 `rem 4294967296 7` 得到 1。新判断要求 `fract() == 0.0`，与 `round?` 的修复一致。i32 溢出错误随之消失，`-2147483648 rem -1` 为 0。

native 与 JS 抛出相同消息，便于同一份 core `:tests` 用 `try` 断言；WASM 没有可恢复的 try，越界输入 trap，与 `&list:nth` 越界一致。

验证：core `&number:rem` 的两个 `:tests` 在 native 上运行，并由现有 `scripts/check-numeric-predicate.mjs` 回放到生成 JS（成功与错误）和 core WASM（成功值）；`scripts/test-wasm.mjs` 覆盖零除数、`-0`、小数、2^53 与 NaN 的 trap，以及结果不为 `-0`。其他整数相关 API（位移、下标）的转换仍在 #1558、#1637 跟踪，本次不改。
