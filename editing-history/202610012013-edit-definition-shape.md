# 定义写入前的形状检查

## 决策依据

#1612 的实际复现表明，`edit def` 会成功写入名称不一致的定义、任意表达式及 Markdown。校验应在保存前发生，并由事务复用，而非依赖后续类型检查才能发现文件损坏。

具名形式检查第二个元素与目标名称一致；已知核心形式直接识别。项目及依赖中的宏使用现有 import 解析与源码读取识别，不执行宏、不激活无关定义，也不按 `def*` 前缀猜测。显式 `--allow-unknown-head` 只跳过未知头部限制。

## 原样写回的兼容边界

全量仓库测试暴露两类现有合法形式。顶层 `fn` 由 Snapshot key 命名，检查其参数列表和函数体，而非把参数表误认成名称。`test-doc-smoke.cirru` 等名义定义的 key 与内部声明名称不同；仅当传入 AST 与已有代码完全相同时保留这种差异，不借原样写回重命名类型。新增或修改代码仍拒绝名称不一致，即使启用未知头部选项也不豁免。

这只是源代码写入边界，不是完整类型证明。源码声明的宏仍可能展开成非法表达式；后续检查负责展开语义。Snapshot 布局、类型系统及后端不变。

## 验证方式

`tests/edit_cli.rs` 验证失败时 Snapshot 字节不变、事务回滚、项目/依赖宏解析、未知头部选项的边界及历史名称差异的不可扩展性。这些属于 CLI 文件系统边界，因此放在 Rust 集成测试，而非重复语言语义测试。

同一回归逐个重放 `calcit/*.cirru` 的持久化定义，并比较所有定义字段的 revision；跳过加载器合成的路径元数据。可通过 `CALCIT_EDIT_ROUNDTRIP_SNAPSHOT` 加入真实消费者的只读源快照，在临时副本上验证，不把生态项目源码复制进主仓库。消费者源码可能有本地修改，记录它的 Git 基线与实际副本验证结果，不把未提交状态描述为正式版本。

完整验证仍按 AGENTS.md 执行：fmt、Clippy、Rust 测试、`yarn check-all` 与实际消费者回归。结果及精确修订写在 PR，而非把此记录当作验收成功声明。
