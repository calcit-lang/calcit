# 0.18.0 WASM / WASI / FFI 发布文档对齐（#1233）

## 背景

实现已经推进（Component Interface IR v4、async export/import、作用域化有界字节流、有界 WASI HTTP
client），但用户文档仍停留在旧 preview / 旧版本。发布 0.18.0 前统一版本组合、能力矩阵与 async
lifecycle 状态。

## 改动

- `examples/wasi-http-client/README.md`：把过期的 `Calcit 0.15.6` 改为当前发布版本 `Calcit 0.17.1`；
  增加稳定 Wasmtime adapter 与 portable WASI 0.3 adapter 的分层说明。
- `docs/installation/wasm-component-boundary.md`：在有界 WASI HTTP 一节明确当前稳定宿主路径使用
  Wasmtime 47 的 WASI 0.2 `wasi:http/outgoing-handler` 传输，Calcit-facing contract 保持 WASI 0.3
  原生 async；portable adapter 仍被 experimental tooling 阻塞。
- `docs/installation/wasi-http.md`：补可复制路径与版本组合（`0.17.1` + `calcit-bindgen 0.1.3`）。
- `docs/installation.md`：补 WASI HTTP starter、FFI async/resource protocol 入口。
- `README.md`：更新 `calcit-bindgen` 状态，说明 0.1.3 已覆盖 async export/import、作用域化有界字节流与
  有界 WASI HTTP client，避免把已完成能力描述为未完成。
- `scripts/wasm-validation.md`：新增「边界分层」，区分表层不支持、预处理后可静态 lowering 的 core/WASI
  command 子集、WASI command 目标与 Component boundary，并指向 Component 类型矩阵作为 source of truth。

## 验证

- 用 `Calcit 0.17.1` 实跑示例命令：`calcit wasm --boundary component`、`calcit ffi export --boundary component`
  成功；再用本地 `calcit-bindgen 0.1.3` 执行 `generate`，产出 `component.wasm`、
  `rust/wasmtime_http_adapter.rs`、WIT 与 manifest。
- `bash scripts/check-docs-md.sh`：69 files / 340 blocks 全部通过。
- 版本组合一致：Calcit 0.17.1 + `calcit-bindgen 0.1.3` + Wasmtime 47.0.4。
