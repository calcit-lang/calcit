# 补齐 JavaScript epoch 毫秒时钟

真实消费者的严格检查和 JS 生成允许 `unix-time-ms`，但 runtime 缺少 `unix_time_ms` 导出，导致浏览器 dispatch 抛错。维护者明确选择使用 `Date.now()` 补齐 JS 实现，而不是改变表层名字、退到单调时钟或仅通过文档隐藏缺口。

公开合同继续是零参数函数返回 Number 毫秒。读取一次宿主系统时钟，合法 epoch 零值原样返回；早于 epoch 时与 native 合同一致失败，宿主读取异常原样传播，不以零或 nil 回退。`monotonic-time-ms` 的实现与经过时间语义保持不变。

用户可观察的基本语义放在 `unix-time-ms` definition 的附带测试，在 native 和 JS 重放同一 AST；确定性毫秒值、调用次数、epoch 前失败与异常身份扩展既有时钟 JS 宿主脚本，不新增检查入口。程序测试和文档通过受保护的 CLI transaction 修改，不直接 patch Snapshot。

core WASM 与 WASI 0.3 command 仍不支持时钟。使用已有 WASM-enabled 源码候选独立重现两项准确的 capability 编译失败后，仅为这项新增附带测试登记两个既有后端限制；原测试及排除集合保留。显式 WASI Preview 1 的固定宿主时钟仍由原夹具验证，没有扩大 Component 能力或静默回退。

发布前须完成原测试、宿主脚本、严格检查、受影响后端及文档验证，等待最新提交实际 review/CI 与精确维护分支合并检查。源码候选验证不冒称已发布 CLI/runtime 配对，消费者浏览器复验仍需真正的新配对版本。
