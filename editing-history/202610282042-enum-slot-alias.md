# Enum 代表值与 type-slot 的静态关系

问题由 Protea 迁移报告的 #2447 引出。最小对照进一步证明，即使入口槽绑定到显式声明 Enum schema 的代表值，传入 Enum 回调也可能失败：TypeRef→AnonymousEnum 的名义类型快捷分支提前返回，跳过了已有别名展开。

已解析的名义 Enum 继续走快捷分支，其余引用进入原别名解析与递归守卫；兼容性与严格证明保持一致。维护者确认支持无 schema 代表值的静态推断，因此入口槽保留原始引用，通过普通预处理及定义推断取得类型，类型关系中只读已编译证据。检查器不执行代表值的运行时初始化，JS 模块原有初始化行为不变。

含入口槽的增量源码变更保守清空编译证据，涵盖代表值的传递依赖，避免旧回调证明继续生效；不另建类型缓存或失效规则。声明 schema、名义身份、未绑定、循环和 Dynamic 边界继续保留，匿名 Enum 不能证明特定名义 Enum 身份。

可观察语义写在共享 fixture 的 :tests，同一组断言分别通过显式与推断 entry 在 native/JS 回放。CLI 负责错误家族、未绑定、循环及检查时不执行初始化的边界；Rust 内部测试只验证同一编译器进程内代表值变化后的失效与重新检查。

审查补充：仅在消费类型注解时准备其引用的入口槽，先应用局部覆盖，并按真实依赖编译代表值；显式 Dynamic 不作为缺失 schema 推断。Snapshot 准备后重查可复用证据，避免重复声明。增量更新在清除编译依赖边之前失效受影响的运行时值。CLI 回归覆盖局部覆盖遮蔽错误代表值、依赖槽顺序与含声明的代表值生成 JS；内部缓存回归覆盖传递消费者及未受影响值。

补充反例确认显式 Dynamic 经过无 schema 别名也曾被重新推断为 Enum。普通定义推断现在在取得名义声明身份后保留显式开放合同，不从初始化器恢复具体值类型；CLI 负例覆盖直接与别名两条路径。
