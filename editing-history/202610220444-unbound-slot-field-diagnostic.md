# Struct 回调的未绑定 slot 诊断

关联 #2113。真实事件回调通过命名 Fn schema 引用 type slot；未绑定 entry 时，原字段检查只显示两个看似相同的函数类型，掩盖了缺少绑定的原因。

保留原有字段关系的通过与拒绝结论。仅在关系已经失败，且已有证明结果明确为 `UnresolvedTypeSlot` 时，复用 `E_UNBOUND_TYPE_SLOT`，指出 Struct 字段路径、调用者源码位置及已有配置命令。声明和使用位置共用同一诊断渲染；普通形状不匹配仍保留原诊断。

不修改 slot 身份、函数方差、名义类型关系或循环保护，不将未绑定 slot 擦成 Dynamic，也不新增 checker、诊断编号、命令或自动修复规则。

验证使用现有编译拒绝 harness：同一回调在 strict/compat 的未绑定情况拒绝，绑定具体名义 Enum 后通过；与修复前二进制进行相同输入、参数的对照。保留并扩展不同 slot、同名 slot 和循环关系的低层断言。这里检查编译失败及源码定位，不新增重复的运行时值测试。

审查补充：沿用已有函数体 hint 的 source-origin 选择原则。回调读取与宏调用属于同一源码定义时保留读取坐标；回调在宏定义内部生成时改指宏调用，不无条件交换 fallback 顺序。新增真实宏展开回归同时覆盖两者，用户回调的精确坐标在修复前实际失败。该回归使用 compat 以到达构造器，而非先被 strict 的未绑定声明检查截获；原 strict/compat × 未绑定/具体 Enum 绑定矩阵不变。
