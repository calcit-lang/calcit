# WASI 目录能力与 JSON 错误边界

WASI 的目录兼容函数接收运行时的可选递归参数。仅接受字面量 `false` 会让未指定递归的 `try-read-dir` 也无法编译；组件能力扫描还需识别该公开入口。WASI 对非递归读取保留 `Result`，动态递归请求返回含 `E_WASM_CAPABILITY` 的错误；直接 `.walk-dir` 仍在编译时报告能力限制。目录原语的两个类型原型在文件访问之前按顺序各求值一次，包括空目录与失败路径；其他后端的递归行为不变。

WASM 的内部 JSON 解析边界现在按顺序求值原型参数，并在输入非字符串时 trap；错误 JSON 字符串继续返回 `Result :err`。由于当前 WASM 表示不能从开放值可靠判断枚举定义，不能证明原型类型时明确拒绝生成，而不是静默生成成功结果。文档不再将移除隐藏 `try` 等同于所有标准库 API 均支持 WASM/WASI。

回归使用 core 定义附带测试重放非递归成功与缺失目录，并在既有 WASI CLI 集成测试覆盖递归限制；WASM 参数求值和动态类型失败属于后端边界，放在现有 WASM CLI 集成测试。完整验证和平台限制以 PR 的实际结果为准。
