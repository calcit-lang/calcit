# 保留函数 bind/apply 的可调用关系

两个方法沿用不同的参数顺序：`m .bind f` 返回 `x → f(m(x), x)`，`f .apply g` 返回 `x → g(x, f(x))`。不根据外部语言或名称推测另一套组合语义，也不增加新的入口。

原参数合同已连接 A、B、C，但返回裸 Fn，导致新函数的 x 成为 Dynamic。采用现有函数体 Map 注解表达输入 A / 返回 C，并把结果补齐为 Fn<A,C>。这与函数 map 使用同一套证明，不修改 Rust 规则或增加按函数名推断的例外。

## 验证与兼容边界

- 原实现与精确合同先在临时 Snapshot 对照：直接/方法调用、非对称参数顺序、String/名义结果、primitive 函数、惰性构造、效果次数与两级错误传播均用同一组 Calcit 表达式回放。
- 共同基线比较完整名义值，因为旧裸 Fn 无法证明字段接收者；新合同额外要求具体 Fn 签名与直接字段读取，不插入转换或 unsafe。
- 生产定义附加这些 `:tests`。原 source-derived harness 同时验证真实 helper 的普通检查、独立 proof 与完整 strict，以及错误输入、错误返回和未知 Fn；检查不改 Snapshot。
- WASM/WASI 先不加排除实际运行，再只记录新增用例的返回闭包、primitive 值与 Ref 不支持；原实现的纯组合也因相同返回闭包限制失败，不宣称新后端支持或降低旧覆盖。
- 函数 mappend 还缺少两个返回容器及 B 的组合能力证明，不是补一个返回注解就能修复。保持原范围，不以本次两项修复声称所有 Fn 方法或整个类型总任务完成。

生产 Snapshot 通过官方 query、事务 dry-run、scoped revision 守卫及 query 读回修改；原参数合同、元数据与运行顺序保持不变。
