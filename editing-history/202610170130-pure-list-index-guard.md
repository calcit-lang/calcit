# 纯 List 索引检查保留条件收窄

qrcode-tetris 的 0.30.1 迁移完整 strict 被 `calcit.core/contains-in?` 阻塞（#2143）。
无依赖的 `contains-in? [[1]] [0 0]` 普通检查与 native 返回 true，严格调用证明却丢失 `number?` 证据。

原因是现有条件证据分析把 `&list:contains?` 视为未知调用，清除前缀 guard；
该原语只检查列表长度和数值索引，不调用用户代码。把它纳入既有纯值原语分类即可，
没有新增推断规则、诊断编号、迁移 fix 或业务豁免。

List 守卫恢复后，严格检查进一步发现 Enum 分支直接把泛型 key 传给数值比较。
该分支在进入比较前显式解码 Number；合法数字路径、边界判断和递归顺序不变，
非法非数值索引仍抛错而不改成 false。错误现在由索引解码给出，而不是后续数值原语；
新增一条附带测试验证“仍然失败”，不依赖旧错误字符串。
这条测试使用 `try`，native/JS 回放；WASM/WASI 的现有能力清单明确记录其
不支持捕获异常，不能把 codegen 拒绝当作行为验证。泛型 List 守卫的正反路径仍在三后端执行。

仍逐项分析原语实参：实参中的未知调用或赋值继续构成副作用屏障。
在现有 short-circuit fixture 的 definition `:tests` 添加泛型索引成功、非法类型、
负数、小数、越界与空列表契约，并复用 native/JS/WASM 回放与严格调用证明入口。
现有拒绝集合增加“纯原语的实参包含未知调用”一项，不放宽作用域/别名证明。

按 #1553 保留 source-level 最小回归；不改 API 签名或合法数据语义，0.30.1 从维护线交付。
