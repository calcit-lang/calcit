# 保留函数组合的输入与输出关系

函数接收者的 `.map` 一直是一元组合：`f .map g` 返回执行 `f(g(x))` 的函数，参数函数先执行，接收者后执行。本次保留方向、惰性构造、参数表达式求值顺序、调用次数与原错误传播，不将它改成集合映射的方向。

原 core 合同已经连接了 `f: B → C` 与 `g: A → B`，却只返回裸 `Fn`。返回函数的 `x` 因此成为 Dynamic，独立证明拒绝将它传给需要 A 的 g。只把返回声明改成 `Fn<A,C>` 仍然缺少函数体证据，不能算修复。

采用现有能力表达完整关系：返回 schema 为 `Fn<A,C>`，新建函数体使用 Map 形式的 `hint-fn` 声明输入 A、返回 C，再由原调用关系检查实际实现。不修改 Rust 证明规则，不增加函数名例外，也不使用两参数 hint 给未知函数赋予具体签名。

## 验证与边界

- 用户语义放在真实 `&fn:map` 定义的 `:tests`：同时验证直接与方法调用、跨类型/名义返回、命名及泛型函数、构造与执行效果、异常传播和显式开放结果的传递。native 与 JS 使用同一个现有运行器。
- 原证明 harness 从官方 query 获取真实源码与 schema，移到非 core namespace 后检查普通 all-defs、独立 proof 和完整 strict，避免 core 兼容边界掩盖证据丢失；检查前后 Snapshot 字节保持不变。
- 反向用例分别尝试用 B 冒充 A、String 冒充任意 C、裸 Fn 冒充具体可调用合同。断言实际诊断；预处理提前失败而没有 JSON 时，仅接受对应的真实 stderr 错误，不把规则目录当作诊断。
- WASM/WASI 实测仍拒绝返回闭包、立即调用返回函数以及 Ref 效果等已有边界。仅为本次新增测试记录逐项排除，不扩大旧测试排除，也不将排除写成后端通过。
- 真实 trait fixture 的函数 map 错误消失后，还会暴露函数 bind 的同类历史问题及其余 trait 证明错误；这些继续留在原类型强化任务中，本次不扩大范围或宣称整个 fixture 严格通过。

Snapshot 变更经官方结构化事务、dry-run 和 scoped revision 守卫完成；没有改变 Snapshot 存储结构、增加公开入口或扩大 Dynamic/unsafe。
