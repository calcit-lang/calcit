# 空集合证据、不可变增长与可写边界

## 实际问题

#2010 来源于 Timegrass #112 的数据库迁移：`Result :ok $ {}` 经过局部变量后变成 `Result<Map<Dynamic, Dynamic>, Never>`，不能证明原有的空用户表初始化合同。直接空字面量能通过的断言，在别名处却失败。#2009 的调用方泛型修复已经解决前一处阻塞，本次不扩展新的 analyzer、fix rule 或 CLI 入口。

## 统一表示与必要的配套修复

空 List/Set/Map 的成员推导为既有的 `Never`，而不是显式开放的 `Dynamic`。普通子类型关系负责将空集合用于具体成员合同；别名、嵌套容器和 Enum 包装不另建证据表。

不能只改字面量的默认值：不可变插入、拼接、合并必须合并旧成员与新成员的证据，不能继续把已插入值的容器当成空集合。相同容器形状的分支合并保留外层形状，不相容的成员才成为 Dynamic。空 Map 的查询允许任意 key，但不会为返回的 Option 制造有效载荷。

已有递归输入求解器从无载荷 Enum 扩展到不可变集合槽位。它使用现有调用合同连接实参之间的泛型关系，只求解编译器拥有的待定变量，不反向特化调用方泛型。普通函数、方法和底层 proc 使用同一合同来源；用户不必将 `.assoc` 改写为底层 proc。Ref 和函数输入不参与空槽位的递归替换。

普通泛型调用保留直接 Never 实参的结果信息，但该实参不限制后续有效实参；同名调用方泛型仍保持刚性。空 Map 查询 lowering 后的 Option 包装因此不会重新变成 Dynamic。

fold 的空初值可由 reducer 的输入合同和集合成员共同推导，包括 `concat` 一类泛型变参回调；不使用 reducer 声明的输出倒推自己的输入。已有 `call-boundary` 附带测试覆盖这一行为。不同调用方泛型的分支不会互相借用证据。

`defstruct` 的两处读取已有 `empty?` 分支保护，改用内部的定下标读取，避免将可空的 `&list:first` 返回值误当作非空字段列表；不改用户定义 Struct 的语法。

CI 的改写后校验进一步暴露了三处配套问题。`interleave` 的非空分支同样改用定下标读取，并在原附带测试补齐双侧空列表与 nil 成员。保留接收者的 `update` 合同包含调用方泛型，不应当成未解出的被调用方变量而丢弃；源树和改写后的直接函数调用都保留这一证据。`assoc-in` 的 Map-only 优化只在替换值符合叶子合同的场景生成同质 Map proc；改变叶子类型时保留原公共调用，不生成绕过检查的内部调用，也不放宽 proc 合同。

文档中的空 Map 计数 fold 使用普通 `assoc`，需要与方法调用共享接收者特化的输入约束。复用既有 core 合同特化来求解待定槽位，并把原文档表达式加入 `:tests` 和三个证明入口；不靠修改示例、添加类型断言或从输出声明借证据通过检查。

## 可写边界

Ref 仍是不变的：无类型上下文的空初始化不允许后续写入使合同变宽。需要可写的空容器时，在初始化位置给出完整类型。

严格模式下，JS FFI 的 `set!` 赋给已知局部变量的值也必须证明该绑定的类型合同；否则后续读取会借用过期的空字面量或谓词证据。诊断复用 `E_CALL_ARGUMENT_UNPROVEN`，并指向赋值及初始化合同。`:js-ffi` 权限要求不变，显式 Dynamic 合同仍可运输开放值。本项随 0.30.0 非 patch 版本交付，不回灌为放宽检查的 patch。

## 验证与消费者边界

语义用例放在 `tests/fixtures/def-value-schema.cirru` 的 `app.empty-evidence` definition `:tests` 中，通过既有统一运行器回放；证明与拒绝用例加入现有 `scripts/check-known-assertion.mjs`。覆盖 Map/List/Set 别名、Result、嵌套空 Map、方法调用增长、递归累加器、空查询，以及非空错误成员、开放来源、遮蔽、重绑定和 Ref 写入。

- 通用集合语义回放 native/JS/WASM。
- Ref 回放 native/JS；不把当前 WASM 不支持 Ref 当作通过。
- `set!` 合法赋值回放 JS，越界赋值在编译阶段拒绝。
- 已有内部 Rust 测试只更新 Never 的内部表示预期，并继续验证调用方泛型及 Ref 不变性。
- 原 helper 负例使用空 List 冒充开放容器，改为包含 Dynamic parser 结果的非空 List，另加空 helper 正例。core 的两个 Ref 记录器显式声明初始化合同：fold-while 为 List<Number>；旧 map-pair 开放二元 List 边界的记录器为 List<Dynamic>，不从示例值倒推公共 callback 的类型。原运行顺序、失败和结果断言不变。
- 全定义严格检查、Rust 单元测试、clippy、TS 编译、Agent 接口与完整 proof 回归分别验证；最终结果及命令保留在 PR。

Timegrass 的原空初始化断言不增加 unsafe、decoder 或层叠断言。更准确的插入推导还暴露了 `users .to-list` 使字符串 key 变成 Dynamic 的旧写法；迁移改用已有 `map-entries`，读取 `MapEntry` 的 `:key` / `:value`，保留解码顺序和首次错误路径。

没有新增依赖、持久审计状态或规则矩阵。额外的递归合同连接只运行于需要求解空槽位的既有准备阶段；普通调用不运行新的分析遍历。消费者剩余诊断继续独立跟进，本项不能代表 Timegrass 全部迁移或 0.30.0 发版已完成。
