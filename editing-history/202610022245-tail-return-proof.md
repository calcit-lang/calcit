# 尾递归与独立返回证据

## 决策依据

在最新 main 的 0.28.0 构建中，`foldl-compare` 的独立 Bool 退出和尾部 `recur` 合并成 Unknown，严格返回审计被拒绝。Diary 的 `prepare-client-patch` 通过依赖进入此处，因此受检 decoder 的普通测试通过并不能证明完整 strict 审计。

不将 `recur` 全局标为底类型，也不使用被审计的返回声明作为递归结果。共享函数返回推断按词法参数契约验证尾递归，合并 if/CoreLet 中真正返回的分支；普通表达式推断保持原样。递归实参证明不能产生新的泛型绑定，因为 recur 保持当前函数的实例，而不是启动一次可重新实例化的普通调用。

只递归没有独立退出的路径保留 Unknown；Dynamic/未知退出不变成具体类型。optional/rest、未覆盖的控制流仍走原有保守边界。代码不添加新诊断、公开工具入口、unsafe 或迁移规则。

## 验证安排

用户可观察的 Bool 比较与 Number 循环放在 definition `:tests`，通过现有 runner 在 native/生成 JS 回放。Rust 仅补内部控制转移/普通表达式区分、刚性泛型参数 invariant，以及现有 fix CLI 的审计、序列化和无写入协议。继续复用全量 core、既有后端 runner 与 CI，真实 patch helper 需重新审计并记录下一项实际阻塞，不提前宣称应用迁移完成。

完整回放越过 `foldl-compare` 后，暴露 `impl-traits` 将已知 List 的尾部 spread 传给 variadic proc 时被拒绝的问题。共享调用证明只在固定参数全部显式提供、末尾恰有一个 spread 时，将原 operand 投影到 `List<rest>` 契约并复用原泛型证明；不合成运行时元素，不改变原调用或求值次数。固定 arity、缺失固定参数、多个 spread、spread 后继续传参仍要求已知展开长度；开放元素不能进入具体 rest 契约。

泛型尾递归的 CLI 用例不能用 `if true`：预处理常量折叠会删除 recur 分支，导致测试实际没有检查递归实参。用 `identical? x x` 保留两条预处理分支；内部 IR 测试直接检查分支合并，不经过常量折叠。

后续回放发现 `&str-spaced` 在非空分支仍将整个列表 spread 到固定 `x0` 参数。现有 List 类型没有长度精化；本次不为内部函数引入平行长度分析，直接在已确认非空的分支将首项与 rest 显式传入，保持原调用的参数序列和 String 返回。新增附带测试覆盖头部标志、nil 跳过、空文本与单项；nil 与非 nil 参数共享的泛型使用既有 Optional 表达，不引入新的 Dynamic 声明。该补充必须经过真实新构建的 native/JS 回放，旧 binary 对新 Snapshot 的测试不足以证明嵌入 core 更新正确。

## 调用泛型的词法作用域

`List<Optional<T>>` 调用 `empty?` 的 `List<T>` 契约时，同名的调用方和被调用方变量触发错误的 occurs check。共享调用证明为被调用变量建立独立实例，参数证明与返回替换共用该实例；调用方变量不能被后续参数重新绑定。源 schema、诊断展示与直接 recur 的刚性契约不改名，原有真正循环变量保护保留。

普通泛型返回、方法返回与 spread 返回复用该环境，不维护分别猜测同名变量是否“传播”的分支。普通推断原有未绑定 payload 保留开放结构的策略不升级成具体证明；严格消费者要求全部需要的输出变量有独立证据。内部测试检查作用域、绑定回滚、循环拒绝和不泄漏实例名；用户语义写入 hint-fn 的附带测试，并加入既有 native/JS 回放。跨后端全量与真实 Diary 审计仍需完成，不能用单项内部测试替代。

只有被调用方声明的泛型属于新的推断实例。闭包参数若引用外层泛型但没有自己声明 `:generics`，必须保持刚性；proc 的签名则隐式量化其类型变量，转换成 Fn 元数据时显式保存该所有权。严格 CLI 的公开定义嵌套用例使用 `List<List<T>>`，避免触发原有公开 API 禁用 legacy Optional 的门禁；core 内部 Optional 复现仍单独保留，不扩大其允许范围。
