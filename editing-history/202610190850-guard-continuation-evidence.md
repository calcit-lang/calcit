# 拒绝守卫的正常继续路径与证据寿命

## 问题与方向

正式 Respo 的 memo 包装函数已经运行 `fn?` 并拒绝非函数，但后续调用仍被普通检查判为 Dynamic；相同调用放在 `if` 成功分支时可通过。这是展开后控制流的证据传播缺口，不应要求消费者改成 unsafe、扩大 Dynamic 或按宏名添加特殊处理。关联 #2184、#2121、#1553。

## 方案

复用既有谓词证据与确定发散分析，对全部正常出口求共同证据，在函数体、core let 与类型槽块的后续表达式使用。`not` 交换真假出口，不解析表层 `when` / `assert` 名称。

词法类型作用域区分独立绑定合同与临时收窄，保存临时收窄前的类型。现有表达式预处理在可能调用用户代码或重绑时撤销临时证据，覆盖参数、条件、初始化表达式及顺序语句。构造函数不等于执行函数；可能逃逸的闭包体清除捕获变量的临时收窄，独立绑定的已检查值保留其合同。立即调用的函数复用既有输入上下文携带执行时机，在参数求值完成后保留当前证据；该标记在进入函数时消费，不传给其内部返回的闭包，owned definition 也不会借用调用方标记。

注解更新不能清除既有证据寿命。原型中实际复现了 `guard → assert-type/hint-fn → 捕获写入 → 返回旧类型` 的误放行；注解现在保留原收窄的撤销信息。作用域不暴露任意可变 HashMap 访问，避免绕开这一生命周期。

## 边界

`fn?` 只产生可调用种类，不生成参数、返回值、rest、async 或宿主权限合同；已知完整签名不被种类证据降级。两参数 `hint-fn` 对未知签名的整体设计仍由 #2172 追踪，本次只处理既有临时证据的寿命，不据此宣布该问题解决。

运行时求值、原有错误、Option 的 None / Some(nil) 身份不变。保留显式 `:js-ffi` 开放调用边界；通过既有返回/参数 proof 拒绝陈旧的具体类型，而不是把开放调用测试误写成应报普通动态调用错误。

## 验证

可观察语义放在 `tests/fixtures/guard-continuation.cirru` 的 definition `:tests`，由现有统一运行器重放 native / JS：参数顺序、调用次数、拒绝错误、Option 身份、Number 方法、词法继续路径和已知函数签名。实际执行 `set!` 的已检查值捕获案例带 `:js` tag，只在 JS 运行：`set!` 为现有 JS FFI 能力，native 本来不实现；类型拒绝边界仍通过原生编译器验证。

不能运行的拒绝案例扩展 `scripts/check-strict-default.mjs`：假谓词、未守卫/反向/可返回的失败分支、直接与捕获重绑、参数/条件/初始化子表达式、逃逸闭包、注解寿命以及种类不能冒充完整签名。临时 Snapshot 通过查询、事务 dry-run 与 scoped revision 组装，不新增 checker、规则或诊断编号。

完整回归还发现 `core/get` 中的 Struct 守卫会在直接字段存在性查询后丢失，造成五项 fix 集成回归提前报 core 边界错误。核对原生实现后，将不调用用户回调的 `&struct:contains?` 与 `turn-tag` 纳入既有只读原语分类，保留原有诊断断言；完整 `fix_cli` 的 131 项回归恢复通过。JS 替代实现仍不能借用未执行的 Calcit 函数体作为副作用证明。

外部回归使用正式 Respo source 副本，记录修复 memo 链后暴露的既有 `get-in` Result 迁移问题，不能将部分恢复或超时记成全项目通过；完整下游迁移仍须独立完成。最终执行 Rust、clippy、完整 strict 与仓库集成验证，PR 的精确 HEAD review/CI 和 main 工作流另在 PR/issue 保留证据。

## 审查与集成回归收尾

审查指出即时函数也可能通过 `recur` 重入。只有进入时成立的捕获证据不能支撑发生过写入的下一轮；对具有词法 `recur` 且可能改变捕获的即时函数，复用现有参数重查的展开代码重放，撤销入口临时证据后重新检查，不重复执行源码宏。只读循环保留入口证据，单纯 `recur` 的转移本身不调用用户回调，实参中的副作用仍必须检查。每轮在体内重新 guard 的程序保留原始错误行为。

完整集成测试发现内层同名 `let` 写入错误地撤销外层 Number guard。证据推导仍保守撤销被重绑的谓词别名；只读性检查只区分当前表达式拥有的局部写入与捕获写入，不借可变别名的旧真假值裁剪分支。现有 `assert=` 展开的 `unsafe-coerce` 只检查实际求值的输入，其类型元数据不被当作执行用户代码；这不增加源码 unsafe 或放宽权限。

另一个审查建议要求注解清除证据寿命记录，未采用：这会重新放行已有的 `guard → annotation → captured write → stale return` 反例。独立声明的函数合同并非临时收窄，用附带测试验证它经过注解与无关副作用后仍保留；同名绑定和捕获写入的原有正反例继续保留，不修改预期。

完整 CI 还指出旧短路负例把函数体明确为 `true` 的 `pretend` 当作未知调用；分析实际函数体后，这已不再是有效的副作用边界。保持原来的拒绝状态、诊断与只读断言，改用签名完整但函数体未知的回调参数；lazy initializer 则显式包含已有打印调用。对应只读函数和谓词别名的允许行为新增为 definition `:tests`，在 native / JS 共用原表达式验证，不通过放宽证明或删除负例消除失败。

后续完整回放还发现 `update` 的 List 分支在索引存在性查询后丢失接收者证据。核对 `&list:contains?` 实现：只做 Number 索引转换与长度比较，不调用用户代码，故纳入已有不调用回调的原语分类；参数求值仍逐项检查，新增捕获写入的拒绝控制。Struct 分支的 `contains?` 可分派用户方法，不能按返回 Bool 宣称只读；在通过 `struct?` 的分支显式绑定已检查的 `receiver`，保留真实方法调用和原求值/失败语义。既有错误回调继续在调用方 argument 3 拒绝，而非提前被 core 内部的陈旧类型阻断。新增用户侧 `.contains-index?` / `.get` 的附带测试覆盖空 List、缺失索引、nil/false payload 与原拒绝错误。

同一回放的泛型控制进一步暴露：正常出口的 kind 收窄在 `let` 返回后覆盖了当前读类型，使已有泛型返回校验看不到原独立 `'T` 合同。`ScopeTypes` 只读提供底层绑定合同给原有 kind-return 关系，不恢复临时读证据、不根据返回声明绑定泛型。新低层 invariant 验证注解/收窄保留原合同、词法 shadowing 替换合同、未绑定值不能产生合同；原五项 Calcit 泛型守卫正反例保持不变并通过。

重入审查还发现丢弃第一遍函数体时，告警、source expression / usage trace 与改写前证据没有同步回滚，可能重复报告或让查询读到旧类型。重放前恢复各集合的 checkpoint，并为既有 post-lowering definition frame 提供局部回滚；首次按需编译、之后仍缓存的依赖告警必须保留。重放复用现有 source replay plan 中已经求值的宏展开，从原始源码重新检查，保留查询坐标、重新记录最终 lowering，不再次求值宏或沿用特化后的旧节点。低层测试验证告警、依赖缓存、查询唯一性与嵌套 frame 隔离；既有 strict 脚本验证实际宏展开只发生一次，原重入拒绝与共享运行时测试不变。

源码重放使两项既有 `.inc` 重入负例更早在原始方法分派处报告 `E_DYNAMIC_METHOD_DISPATCH`，而非在已经特化的原语参数处报告 `E_CALL_ARGUMENT_UNPROVEN`。两项仍必须拒绝，预期分别精确使用现有方法诊断；直接 `&+` 负例仍要求原参数证明诊断，不采用宽泛匹配或删除断言。
