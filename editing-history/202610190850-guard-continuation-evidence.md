# 拒绝守卫的正常继续路径与证据寿命

## 问题与方向

正式 Respo 的 memo 包装函数已经运行 `fn?` 并拒绝非函数，但后续调用仍被普通检查判为 Dynamic；相同调用放在 `if` 成功分支时可通过。这是展开后控制流的证据传播缺口，不应要求消费者改成 unsafe、扩大 Dynamic 或按宏名添加特殊处理。关联 #2184、#2121、#1553。

## 方案

复用既有谓词证据与确定发散分析，对全部正常出口求共同证据，在函数体、core let 与类型槽块的后续表达式使用。`not` 交换真假出口，不解析表层 `when` / `assert` 名称。

词法类型作用域区分独立绑定合同与临时收窄，保存临时收窄前的类型。现有表达式预处理在可能调用用户代码或重绑时撤销临时证据，覆盖参数、条件、初始化表达式及顺序语句。构造函数不等于执行函数；可能逃逸的闭包体清除捕获变量的临时收窄，独立绑定的已检查值保留其合同。立即调用的函数复用既有输入上下文携带执行时机，在参数求值完成后保留当前证据；该标记在进入函数时消费，不传给其内部返回的闭包，owned definition 也不会借用调用方标记。

注解更新不能清除既有证据寿命。原型中实际复现了 `guard → assert-type/hint-fn → 捕获写入 → 返回旧类型` 的误放行；注解现在保留原收窄的撤销信息。作用域不暴露任意可变 HashMap 访问，避免绕开这一生命周期。

## 边界

`fn?` 只产生可调用种类，不生成参数、返回值、rest、async 或宿主权限合同；已知完整签名不被种类证据降级。两参数 `hint-fn` 对未知签名的整体设计仍由 #2172 追踪，本次只处理既有临时证据的寿命，不据此宣布该问题解决。

运行时求值、原有错误、Option 的 None / Some(nil) 身份不变。保留显式 `:js-ffi` 开放调用边界；通过既有返回/参数 proof 拒绝陈旧的具体类型，而不是把开放调用测试误写成应报普通动态调用错误。

## 验证

可观察语义放在 `tests/fixtures/guard-continuation.cirru` 的 definition `:tests`，由现有统一运行器重放 native / JS：参数顺序、调用次数、拒绝错误、Option 身份、Number 方法、词法继续路径和已知函数签名。实际执行 `set!` 的已检查值捕获案例带 `:js` tag，只在 JS 运行：`set!` 为现有 JS FFI 能力，native 本来不实现；类型拒绝边界仍通过原生编译器验证。

不能运行的拒绝案例扩展 `scripts/check-strict-default.mjs`：假谓词、未守卫/反向/可返回的失败分支、直接与捕获重绑、参数/条件/初始化子表达式、逃逸闭包、注解寿命以及种类不能冒充完整签名。临时 Snapshot 通过查询、事务 dry-run 与 scoped revision 组装，不新增 checker、规则或诊断编号。

外部回归使用正式 Respo source 副本，记录修复 memo 链后暴露的既有 `get-in` Result 迁移问题，不能将部分恢复或超时记成全项目通过；完整下游迁移仍须独立完成。最终执行 Rust、clippy、完整 strict 与仓库集成验证，PR 的精确 HEAD review/CI 和 main 工作流另在 PR/issue 保留证据。
