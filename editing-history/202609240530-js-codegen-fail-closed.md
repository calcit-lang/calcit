# JS 产物写入必须失败封闭

## 缘由

#1311 发现 JS 生成的目录创建和文件写入都忽略了 I/O 错误。不存在的多层 `--emit-path` 会让 CLI 输出 `emitted` 并以零状态结束，但文件并未产生；目标路径是普通文件时也会误报成功。这会让 Agent 和 CI 将不存在的 JS 产物当作可运行结果。

## 决定与边界

- 输出目录递归创建；不能用作目录时立即返回带路径的错误。
- JavaScript 模块、诊断 sidecar 和同一 codegen 路径的 IR 产物均传播读写错误。成功写入日志延迟到整个 JS 生成完成后输出，避免部分生成失败时出现误导性成功记录。
- 不引入新的 CLI 入口或产物原子提交协议。失败仍可能留下已经写入的部分文件，调用方必须以退出状态和实际产物共同判断；下一次运行可复用未变化的内容。

## 证据

新增真实 CLI 回归，覆盖不存在的父目录、输出目录位置被普通文件占用、单个 JS 模块路径被目录占用，并检查状态、诊断和实际产物。两个主要场景在修复前均以零状态误报；修复后均满足预期。低层单元测试覆盖写入失败不会返回 `written=true`。这属于 #1302 的 Agent 任务基线中的一个确定性失败案例，不以模型跑分衡量。
