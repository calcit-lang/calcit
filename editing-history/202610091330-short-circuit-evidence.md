# 短路条件中的确定类型证据

## 动机与范围

已发布 Recollect 0.0.57 的受检 patch API 在 Diary 严格检查中被阻断：`and` 内依次验证 Number、整数与索引范围，成功分支的 `&list:assoc` 仍把索引视为 Dynamic。相同代码改成嵌套 `if` 则通过。关联 #1865、#1529、#1553。

修复放在共同预处理的条件证据提取层，不根据 `and` / `or` 的名字信任宏，不添加新的公开命令、诊断或固定改写规则，也不修改模块缓存或扩大应用类型。

## 设计

- 在已经展开的 `if` / `&let` 上计算真、假结果各自确定成立的局部证据；不可达结果与“可达但无证据”分开表示。
- 顺序执行累积证据，分支汇合只保留相同事实；原有可信 core 谓词和名义 origin 校验继续复用。
- 局部谓词结果可在同一条件表达式内通过绑定传递；离开作用域清除绑定名，遮蔽时清除旧同名证据。
- 未知调用和局部写入作为 effect barrier；仅有限的无用户回调原语、bundled 比较和已知 List 的 `count` 可保留前序证据。声明 Bool / Number 返回值本身不是无副作用证明。
- 分析有深度与节点上限，超限放弃证明，不猜测类型；不修改运行时求值或生成源码。
- 此次不扩张泛型返回的 refinement 规则，也不引入跨定义 effect inference。

## 验证

在现有 `def-value-schema.cirru` 加 Calcit definition `:tests`，包括原 compound / nested 对照、合法与非法索引、多变量、`or` 共同证明、假分支、词法谓词结果及短路求值次数。现有 `check-known-assertion.mjs` 使用统一 runner 回放原 AST，并检查未证明分支、遮蔽、用户 Bool 函数、未知调用和 `set!` 的拒绝及 Snapshot 不变。

完整 native / JS 回放；WASM 回放已验证的三个标量定义。集合索引和含比较的 `or` 在额外 WASM 探针中出现运行时 trap，另行跟踪，不计为本次已支持能力。Diary 原 strict 重跑到动态 Struct 字段写入处，暴露下一项独立边界；不能把最小复现通过写成全应用通过。确切命令、结果与后续 issue 链接保留在 PR。
