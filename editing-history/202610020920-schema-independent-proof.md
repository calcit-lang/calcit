# schema 合成中的独立证明

## 问题与决策

`synthesize-schema-v1` 曾仅凭候选不含剩余 Dynamic 洞就授予自动写回。
正常预处理允许迁移中的浅断言和显式信任契约；这些类型元数据可能来自返回声明、
`assert-type` 或 `unsafe-coerce`，不能作为它们自己的实现证明。
最小复现从 Cirru EDN 读取 nil，在局部断言后返回同一值，旧工具却自动写入 Number 返回 schema。

继续复用现有候选、共享类型证明、断言审计和 suggestion/事务入口，避免新增规则入口、
独立类型模型或质量统计。合成仍在兼容迁移模式下处理缺失声明，但必须另行确认实现和实际调用点的证据。
候选与证明分开：证据不足时保留 needs-review 候选，自动 operation 为空；只读全项目查询继续处理其他定义。
原始编译器诊断和位置复用现有 compiler-diagnostic origin，未知与矛盾不会被空的 unresolved 列表掩盖。

证明审计使用强转输入的实际类型，普通编译继续保留显式信任契约。
真实 decoder 和已证明断言可继续合成；丢弃的强转结果不影响独立的字面量返回证明。
macro 实现和求值属于生成源码的阶段，展开后的源码才接受调用者的运行时证明审计，
不按 core namespace 豁免运行时实现。此失证据用例属于后续 #1553 改写后校验回归的输入。

审计产生的临时局部类型不得污染普通编译缓存。最外层审计保存并恢复已有 compiled cache，
错误和 panic 同样恢复；嵌套审计共享外层 checkpoint。该路径只用于显式审计，不改变普通运行。
checkpoint 与其他全局编译状态修改一样，要求编译器状态的独占使用；后续真实项目验证同时观察显式查询成本。

调用点审计沿用 Snapshot source 编译入口，该入口与普通定义编译共享相同的证明模式缓存政策，
在证明模式下重新处理源码。最小负例先预热一个调用方，
其调用实参是字面量，但随后依赖未证明断言返回 Number，旧路径会漏掉该 owner 的证明义务。
回归先在旧路径失败，再要求保留该断言的实际 owner 与坐标，且 apply 不写回。
缺少 schema 或具有开放返回契约的函数在审计中可复用现有 implementation 推导，
避免把可独立证明的调用返回误报为 unknown；只读取实际返回证据，不修改普通编译的显式 Dynamic 契约。
泛型调用继续复用既有参数绑定与返回替换；沿用 callable 返回推导的递归保护，循环调用仍保持未知，且 unwind 后恢复保护状态。

## 验证契约

- CLI 事务回归验证未证明断言的原始位置、producer 声明、强转返回和强转实参，不允许自动写回，原始字节保持不变。
- 正面语言契约放在通过 CLI 创建的 definition `:tests`：字面量断言、真实 decoder 和不参与返回证明的强转均返回 3。
- Rust 只负责候选适用性、事务无写入与缓存隔离；缓存覆盖成功、错误及 unwind。
- 既有精确候选、参数调用约束、部分洞、WASM import、重复 preview 和全项目 schema 查询继续回归。
- 完整 fmt、Clippy、Rust、Node/Agent、后端和安装后 Respo 验证仍是提交 PR 的门槛。

本次不新增 concrete-return/callable/nominal-write 规则，不自动选择 decoder、授予 FFI 权限、扩大 Dynamic，
也不将 schema 候选存在等同于所有运行时边界已验证；#1539 的其余任务继续保持开放。
