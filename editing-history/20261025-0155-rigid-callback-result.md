# 回调返回不得替换已经确定的泛型

## 问题与决定

`.foldl` 上下文修复的最终独立补审发现了现有共用回调返回检查的漏洞。函数合同
`<Elem, Acc>(List<Elem>, Acc) -> Acc` 中的两个类型参数是独立的，但回调返回 `item`
被“返回自己的一个输入参数”捷径接受；以 Number 成员、String 初值调用时，普通检查通过而
实际返回 Number。旧前缀 `foldl` 已有此漏洞，新方法上下文扩大了影响，不能把两者混为一次新回归。

修复沿用现有回调 expected context 和 identity-aware return proof：只有仍由被调用函数拥有的
输出推断变量可以由回调输入推断；已经确定的调用方词法类型仍须证明返回身份相同。
这不是针对 `foldl` 名字的新规则，也不新增 checker、诊断、公开 API、固定迁移、unsafe 或 Dynamic。
该严格拒绝属于既有普通检查/方向证明收敛工作，不混入仅允许诊断改善的补丁范围。

## 兼容边界

错误的独立泛型关系现在使用原 `E_ERASED_GENERIC_RELATION` 拒绝。原始函数参数、求值顺序和
运行时不变；真实的同型合同应由用户明确声明，编译器不自动把两个 binder 合并。
待推断输出仍可从输入证据求解，合法独立累加器、空集合及嵌套列表拼接必须继续成立。

## 验证

修改前固定 CLI 在前缀、方法、后缀和线程宏四种形式都错误接受 Number 成员/String 初值，
实际返回 Number；修改后四种形式均在回调源码处拒绝，合法返回 `acc` 的四个控制继续通过。
定义自身新增 Calcit `:tests`，覆盖两种不同型累加器及空集合；与原拼接回归一起在
native、JS、WASM、WASI 各实际通过 2/2，零排除。Snapshot 用官方事务、scoped revision 和
完整解析比较确认只增加该测试。现有宿主脚本逐例建立独立 fixture，检查四个编译入口拒绝、
准确的源码 owner、无错误产物及无内部类型 ID 泄露；WASM 的全项目预处理不能让另一个非法定义代替当前反例。
原全量 Cargo、Clippy、check-all 与最新提交 CI/review 仍须验证；窄回放不替代这些门槛。
