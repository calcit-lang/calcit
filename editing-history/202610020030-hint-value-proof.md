# 函数元数据与回调值的类型边界

官网的示例切换回调曾把 `(hint-fn schema (fn ...))` 当作函数值。native 的 `no_op` 返回 Nil，JS 表达式生成也返回 `null`，但预处理仅为零参数 `hint-fn` 推导 Nil；带元数据的形式返回未知推导结果，具体函数参数检查因而跳过，直到实际调用才报错。

本次按已有语义修正通用表达式推导：`hint-fn` 表达式返回 Nil，不是函数包装器。正常的一参数函数体注解和二参数局部绑定注解仍保留签名作用。函数体中的一参数元数据会由运行时移除，因此返回检查必须与执行体一致，跳过这类元数据；没有实际执行表达式的函数返回 Nil。零参数旧 `;nil` 标记和二参数注解不属于可移除的函数体元数据。签名提取只将一参数注解用于外围函数，JS/WASM 函数体也不再删除二参数注解。

复用既有参数、返回和断言诊断，不增加新的命令、统计规则或隐式类型转换。纠正 `hint-fn` 内嵌文档和 syntax 签名，避免 Agent 被“返回 hinted function”的旧说明误导。

五个 definition `:tests` 覆盖元数据值、局部注解、正常带类型回调、末尾函数体注解和二参数注解不会偷换外围函数签名/返回值；现有 known-assertion 运行器将相同表达式回放到 native 和实际生成的 JS。负例覆盖直接回调、局部绑定、局部函数注解、helper 返回、跨命名空间函数参数、断言和空执行体，要求 native/check-only/JS/WASM/WASI 在预处理阶段拒绝，不生成目标产物。旧 WASM、EDN 和类型 fixture 的空 Unit reload 函数体改为显式 `&unit`，没有改变测试预期。WASM 的成功回放仍限定在已有标量子集，本次不宣称扩大其 Nil 或高阶函数执行能力。

这是 #1542 的确定性漏检修复和 #1553 的回归证据，不代表完成外部 Dynamic 的深层证明、Ref 别名所有权或全部回调契约。
