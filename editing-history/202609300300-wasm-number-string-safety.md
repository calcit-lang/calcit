# WASM 运行时 Number 文本转换的安全边界

## 问题与决策

#1456 的原有 `turn-string` WASM helper 对运行时小数返回字面量 `number`，而不是数字文本；对静态 Number 参数中的 0，通用 f64 值分支还会误判为 nil 并返回空串。运行时大整数可能进入 i64 截断路径，产生陷阱或与 native/JS 的最短十进制表示不一致。

本批把静态 Number/Numeric 直接 lower 到数字转换 helper，避免 0 被 nil 分支吞掉。helper 只接受可精确表达且与普通十进制整数文本一致的安全整数（绝对值不超过 2^53）；小数、负零、超范围值以及 NaN/无穷值明确陷阱，不再返回伪造文本。literal 的编译期格式化路径仍保留，不受运行时限制。

## 后续边界

这是一项避免静默错误的修复，不等于完成 WASM 的 f64 转文本。完整实现需要与 native/JS 一致的最短十进制算法和负零、非有限值处理；#1456 保持开放。动态值在当前 WASM f64 表示中仍可能混淆 nil 与 Number 0，不能把这一修复写成 Dynamic 转换已经安全。

## 验证

集成脚本通过真正的 WASM export 传入运行时 Number，验证 42、0、2^53 的正确文本，以及 0.5、负零、2^53 以外、无穷值和 NaN 均显式陷阱。Calcit 全量检查、Rust 测试和 Clippy 用于防止既有 WASM 路径退化。
