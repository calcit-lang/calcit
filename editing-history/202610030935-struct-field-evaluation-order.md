# 名义 Struct 字段求值顺序与布局分离

## 复现与选择

#1696 的迁移回放使用先写状态、后读状态的字段，暴露直接名义构造的 lowering 会按字母排序后的字段布局
重排 payload。相同构造在旧字段对与直接语法之间因而改变结果与失败顺序，不能把这个差异当作安全迁移。

共同 preprocessing 继续进行原字段完整性与类型校验，但输出显式 tag/value 对时保留源码顺序，
缺省字段随后追加。native 和 JS 原构造过程已经按 tag 定位名义槽位，不需要新 wrapper 或运行时协议。
WASM 同样在生成 payload 前验证完整 tag 到槽位的映射，然后按源码顺序求值并存入对应布局位置。
不改变名义身份、字段类型、存储布局，也不扩大 Dynamic。

## 验证

新增 definition `:tests` 与现有 WASM fixture 导出定义共同覆盖正反字段顺序、一次执行和正确字段值。
失败用例验证第一个字段报错后第二个字段不执行。现有 struct JS 与 WASM 运行器观察相同 Calcit 源码的输出，
不新增运行器或另写一套业务语义断言。WASM 日志解码复用现有从模块恢复类型 tag 的字符串解码，
移除旧硬编码，避免把新的字符串地址误记为数字。

附带构造器迁移另外按原样断言回放状态依赖，保证修复不是修改预期以适应字段重排。
#1714 单独交付这个语言语义修复；#1696 继续补齐剩余规则与弃用元数据。
