# 全项目 fix 预览加载多入口依赖

关联 #1315。`--check-only` 按选定入口加载模块；`fix --preset surface-latest-v2` 则会遍历整个项目的定义。此前 `fix` 仍只加载选定入口的模块，所以另一个入口独有的依赖虽能通过该入口的严格检查，却会在全项目预览中被误报为未知定义。

现在仅对 `fix` 命令合并各入口声明的模块路径，保留选定入口的优先顺序，并按入口名稳定遍历其余入口、去重加载。其他命令的依赖范围不变。真正缺少定义时，错误仍然非零退出，指明正在预处理的定义和缺失项，并提示用 `config modules --entry` 检查各入口声明。

CLI 回归构造默认入口和 `prime` 入口，后者独有模块供项目中另一个定义引用：两个入口的严格检查及全项目预览通过，预览不写回 Snapshot；移除模块声明后，预览应失败并给出修复线索。另在隔离副本中复现 Cumulo Reel 的旧错误，更新副本中的 Calcit 版本声明以匹配本机 0.20.0 二进制后，两个入口严格检查及全项目预览通过，原仓库与业务 Snapshot 未修改。

生成代码验收尚未通过：server JS 能生成，但 `node --check` 在 `cumulo-reel.app.server.mjs` 中发现重复的 `$cumulo_reel_DOT_schema` 命名空间导入。这是与 `fix` 模块加载无关的 JS emitter 问题，需单独修复后重跑消费者运行验证；不把检查通过等同于消费者已可运行。
