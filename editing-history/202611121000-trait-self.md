# trait 方法签名的隐式 `Self` (#2727)

- 决定：`deftrait` 方法签名里的 `Self` 是隐式的接收者类型参数。compact `Fn` 与规范 `(:: 'Fn {…})` 两种写法都由 `builtins::meta::with_implicit_self_generic` 补进 `(:generics …)`。它挂在 `qualify_trait_member_type_form` 入口，所以运行时 `&trait::new` 与源码解析 `parse_deftrait_source` 看到的是同一签名。这是 trait 重做的第一步，设计文档与 Jon 2026-11-12 的 6 个决定见 project memory `calcit-trait-redesign-2727`。
- 规则：用了 `Self` 的 trait，每个方法首参必须是 `Self`，否则报 `E_TRAIT_SELF_RECEIVER`。只服务一种接收者的 trait（core `OptionOps` 的 `Option T`、`FsPathOps` 等）照旧写具体类型。这一点是 Jon 在 09:39Z 确认的细化，原本要求所有 trait 首参都是 `Self`。
- 修补：签名里写 trait 自己的名字报 `E_TRAIT_AS_TYPE`，补上 #2704 留下的缺口。未声明的短名在 `Fn` schema 里会被解析成类型变量，所以检查同时看 `TypeRef` 与 `TypeVar`。external-object trait（CodeEntry `:ffi`）的成员以宿主句柄类型作接收者，不受这条限制。
- 检查位置：`expand_macro_call` 里 `deftrait` 宏调用处，在 `reject_legacy_trait_method_tag_syntax` 之后。
- core：`Add`、`Compare`、`Contains`、`Countable`、`Debug`、`Emptyable`、`Eq`、`Len`、`Mappable`、`Multiply`、`Serialize`、`Show`、`Sliceable`、`ToString` 改写为 `Self`，签名含义不变。`Deserialize`（首参是 `String`）不改。
- 未做：`defimpl Type Trait` 与编译期挂载属于下一步。`defimpl` 内联 lambda 的参数暂时仍不从 `Self` 推断。
- 验证：`calcit/type-fail/trait-self-receiver.cirru` 与 `trait-names-itself.cirru` 对应 Rust 测试 `strict_type_fail_deftrait_self_receiver_and_self_reference`；单测 `implicit_self_generic_is_added_to_trait_fn_schemas`；`calcit/test-traits.cirru`；core 单元测试 `CALCIT_LINT_CORE=1`。
