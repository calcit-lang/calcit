# Enum 构造中的调用方泛型保留

## 背景与决定

Timegrass 的 `validate-stored-users` 已有 `Map<String,T>` 参数合同，但包装成
`Result :ok users` 后，既有严格断言证明将载荷报告为 Dynamic（#2008、#1916）。
最小复现与正式 fixture 均先确认失败；与 #1553 的改写后证据原则一致，修复
构造器推导，不在消费者增加断言或改变业务类型。

Enum 载荷原先直接使用定义中的泛型名做绑定。若调用方也使用 T，实际类型
`Map<String,T>` 绑定到构造器 T 时会被误认为递归类型；直接载荷 T 也可能因为
同名比较成功却没有留下绑定而退化为 Dynamic。改用 Struct 构造和普通调用已有的
`CallTypeProof`，为构造器变量建立独立作用域，保留调用方变量的刚性。

## 边界

未参与当前 variant 的泛型参数继续为 Never；未证明的载荷维持原来的开放类型
回退。没有新增规则、诊断编号、公开命令、运行时转换或新的不安全边界。
不允许构造器把调用方的任意 T 特化成 Number，也不允许开放载荷冒充具体类型。
调用关系允许某些开放值与捕获泛型一起传递；数据构造还必须让每个载荷独立证明
其推导后的字段类型。因此推导完成后，使用同一证明机制在无构造器泛型的作用域
复核载荷，防止第二个 Dynamic 载荷借用第一个载荷的 T。

## 验证方式

在现有 `def-value-schema.cirru` 中增加 definition `:tests`，覆盖同名与异名泛型、
直接载荷、Map 嵌套、Result 错误槽及重复载荷；通过统一运行器回放 native/JS/WASM。
现有 `check-known-assertion.mjs` 检查断言、返回和调用证明，以及开放/错误载荷、
调用方特化和重复泛型不一致的拒绝行为，并确认检查不改写 Snapshot。
另外复验 Timegrass 的原定义和完整严格工作流；单项通过不代表其完整迁移完成。
