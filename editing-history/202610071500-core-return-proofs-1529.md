# calcit.core 返回与参数证明（#1529）

Diary strict workflow 在 `calcit.core` 内部报告的 `E_FN_RETURN_UNPROVEN` / `E_CALL_ARGUMENT_UNPROVEN`
由 core 自己的契约与实现造成，修复放在 core 源码与共同证明关系中，不豁免 core，也不使用
`unsafe-coerce` 或把声明放宽为 Dynamic。

## 通用关系

- 返回泛型 `'T` 的函数，若参数类型正是该 `'T`，`list?`、`map?`、`string?` 等类别谓词守卫的分支把 `'T`
  视为对应类别，分支出口按该类别证明（`refined_generic_return_is_proven`）。未被守卫的出口、作用于其他值的
  谓词和开放结果仍须证明原泛型契约；回归见 `scripts/check-known-assertion.mjs` 的 `kind-*` 用例。
- 返回证明检查 `if` 出口时按预处理同样的谓词收窄分支作用域，使 `(if (struct? result) result ...)`
  这类受检解码能证明收窄后的出口。

## core 源码

- `slice` 统一经 `Sliceable` 的 `.slice`，返回 `C` 由 trait 合同证明。
- `includes?` / `empty?` / `contains?` 的开放 `.method` 结果经 `bool?` 受检解码，不再依赖声明。
- `contains?`、`assoc` 的 list/string 分支先用 `number?` 收窄键；`dissoc` 的 list 分支要求唯一的 Number 索引，
  map 分支取首个键并展开其余键，使 spread 有静态固定参数。
- `assoc` 的 struct 分支经未收窄别名调用 `.assoc` 后检查 `struct?` 结果，因为动态字段写入无法静态证明；
  不支持的接收者明确 raise，不再回落到未知方法。
- `rest` 同样只接受 list/string；`&map:map` 回调使用 `List<Dynamic>` pair 合同并返回 `Map<Dynamic, Dynamic>`，
  由 `&map:fold-kv` 取得键值，不再用无法证明的自由泛型 `P/Q/R/S`。

## 兼容边界

非 list/map/struct/enum 接收者上的自定义 `.assoc`、非 list/map 的 `.dissoc`、非 list/string 的 `.rest`、
以及 `contains?`/`includes?`/`empty?` 返回非 Bool 的自定义方法，现在在 core 入口显式 raise，不再静默透传。
`dissoc` 在 map 上不再接受零个键。验证：definition `:tests`、`yarn check-all` 与 Diary strict 复现。
