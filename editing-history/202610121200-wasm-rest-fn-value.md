# WASM 通过函数值调用带 `&` 参数的函数

关联 #1972、#1966、#1964。#1966 把函数表中 `&` 函数的入口改为 `() -> ()` 的 trap 函数，避免间接调用把普通实参当作 rest List；代价是 `let ((f +)) (f 1 2)`、经定长 Fn 参数传入 `defn first-of (a & _xs) a` 再以 2 个实参调用等写法在 WASM 上 trap。立即调用的带 `&` / `?` 参数的 `fn` 若函数体使用 `recur`，也直接 trap。

## 决策

函数值的编码不变，仍是函数表 slot 编号。改为每个调用实参个数一张函数表：用 N 个实参调用函数值时，`call_indirect` 使用规范类型 `(f64 × N) -> f64` 和第 N 张表。第 N 张表中，`&` 前有 k 个参数且 k ≤ N 的函数，入口指向一个类型为 `(f64 × N) -> f64` 的适配函数：它把后 N - k 个实参打包成新 List，再直接调用原函数；其余入口仍是函数本身，参数个数不符时签名检查失败而 trap。只有实际出现的调用实参个数才生成适配函数和填充对应的表；其他编号的表为空表，表 0 始终填充。

没有采用“每个 slot 记录 rest 元数据、在调用点运行时分派”的方案：那需要在每个间接调用点读取元数据并按 k 的取值分支打包，会给定长函数值调用增加开销与代码体积。多张表的方案中定长调用的指令序列不变（只是表编号随实参个数变化），打包逻辑集中在每个 `&` 函数、每种调用实参个数一个的适配函数中。

`recur` 改为按调用的规则绑定参数：缺省的 `?` 参数为 nil，`&` 参数收到剩余实参组成的新 List。这同时适用于立即调用的 `fn` 与带这类参数的 `defn`，与 native 中 `recur` 重新走参数绑定一致。展开形式的 `recur a & xs` 维持原有行为。

`calcit wasi` 的 command 仍在编译期以 `E_WASI_COMMAND_INDIRECT` 拒绝可执行到的间接调用，本次不改变。

## 验证与兼容

`hint-fn#plain-call-rest-fn-value` 补充了 1、2、3 个实参调用 `+`、定长函数值与经 `map` 的动态回调，移出 WASM 排除清单；WASI 排除项保留。新增 `hint-fn#iife-rest-param-recur` 覆盖 `&` 与 `?` 参数的 `recur`，在 native/JS/WASM 通过。Rust 测试 `rest_function_table_slots_pack_trailing_arguments` 覆盖多张函数表的入口与适配函数的打包、定长入口的签名失败。

用户可见变化：WASM 上通过函数值调用 `&` 函数、在带 `&` / `?` 参数的立即调用 `fn` 中使用 `recur`，现在返回与 native 相同的值。函数值调用的实参少于 `&` 之前的参数个数时仍会 trap。
