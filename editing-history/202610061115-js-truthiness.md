# JS 条件语义对齐

Feather 迁移中的真实附带测试在 native 通过、同源 JS 失败。无模块复现确认 JS conditional lowering 直接使用自动布尔转换，令 `0` 与空字符串选择错误分支，而 native 只把 nil、false、Unit 视为假值。

在共享 `gen_if_code` 的表达式与语句路径统一生成条件：直接生成 `((condition) ?? false) !== false`，将 nil/Unit 的 JS 表示归为 false 后严格比较，不触发自动布尔转换或 host coercion hook。条件只求值一次，0/空字符串/NaN 等保持真值，不扩大 Dynamic，不增加公开 proc、CLI 或迁移规则。`or`/`and` 保留原 macro 展开与既有 false 返回合同。

十二组 core definition `:tests` 覆盖真假值、开放与 Bool 输入、嵌套表达式/尾部条件、短路、身份、求值次数和失败传播。`unsafe-coerce` 只修改静态信任合同，运行值仍须按 Calcit 真假值判断；附带测试在显式 `:js-ffi` adapter 内验证直接表达式、局部绑定、嵌套条件及 Bool producer 返回。复用既有严格检查运行器回放同一 AST，并检查 JS host-only 值及统一 codegen。保留所有原测试与门禁；WASM 仅验证其已支持的子集，不扩张其语言支持范围。

Review 确认新增 runtime helper 会让未发版候选与已发布同版本包之间出现 ABI 缺口，而仅排除直接 unsafe 条件也无法覆盖别名。最终移除新 helper 和基于静态 Bool 的条件特例，统一内联语义表达式，不引入 unsafe 来源追踪或逐版本能力矩阵。严格类型检查照常保留；这里放弃的是非必要的 JS 条件微优化，不是 Bool 类型约束。已发布旧 runtime 也无需新增导出即可执行新生成代码，版本号仍按仓库合并后发版流程升级。

实际 WebAssembly 回放确认另一个既有缺口：`Number -> Number` 的 `(if x 1 2)` 在 native 对 0 返回 1，而 WASM 对 0 返回 2。现有 WASM scalar ABI 需要利用类型区分 Bool false、Nil/Unit 和 Number 0，开放/Optional 条件还涉及表示证据；本次不混入这项更大的边界调整。只将两组 Bool/静态假值合同纳入实际 WASM 回归，其余差异在 #1781 保持开放，并在用户文档注明。

关联 #1781、证据保持回归 #1553；正式发布前仍须完成最新 HEAD review/CI、精确 main 验证与真实 registry/消费者验收，不能用候选通过关闭发版门槛。
