# JS 条件语义对齐

Feather 迁移中的真实附带测试在 native 通过、同源 JS 失败。无模块复现确认 JS conditional lowering 直接使用自动布尔转换，令 `0` 与空字符串选择错误分支，而 native 只把 nil、false、Unit 视为假值。

在共享 `gen_if_code` 的表达式与语句路径统一生成条件：复用已经预处理的 lexical/compiled 类型信息，精确 Bool 保留直接分支；其他条件调用内部 runtime helper，以三种值的严格身份判断真假值。helper 参数正常求值一次，不触发 host coercion hook，不扩大 Dynamic，不增加公开 proc、CLI 或迁移规则。`or`/`and` 保留原 macro 展开与既有 false 返回合同。

十二组 core definition `:tests` 覆盖真假值、开放与 Bool 输入、嵌套表达式/尾部条件、短路、身份、求值次数和失败传播。直接 `unsafe-coerce` 条件不借用目标 Bool 声明启用 JS 优化：该构造只修改静态信任合同，运行值仍须按 Calcit 真假值判断；附带测试在显式 `:js-ffi` adapter 内验证语句与表达式路径。复用既有严格检查运行器回放同一 AST，并检查 JS host-only 值及 Bool codegen。保留所有原测试与门禁；WASM 仅验证其已支持的子集，不扩张其语言支持范围。

实际 WebAssembly 回放确认另一个既有缺口：`Number -> Number` 的 `(if x 1 2)` 在 native 对 0 返回 1，而 WASM 对 0 返回 2。现有 WASM scalar ABI 需要利用类型区分 Bool false、Nil/Unit 和 Number 0，开放/Optional 条件还涉及表示证据；本次不混入这项更大的边界调整。只将两组 Bool/静态假值合同纳入实际 WASM 回归，其余差异在 #1781 保持开放，并在用户文档注明。

关联 #1781、证据保持回归 #1553；新编译器与包含内部 helper 的 runtime 必须一起发布。正式发布前仍须完成最新 HEAD review/CI、精确 main 验证与真实 registry/消费者验收，不能用候选通过关闭发版门槛。
