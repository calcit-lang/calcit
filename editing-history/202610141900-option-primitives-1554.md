# 底层缺失值原语返回 Option（#1554）

## 背景

PR #2058 把 13 个返回 `Optional<T>`（nil 或 T）的内部 `&` 原语的 nil 行为用测试固定下来。负责人反馈：不能继续规范化 nil，要更激进地迁移到 Option。

## 决策

- 13 个原语直接返回名义 `calcit.core/Option`，不再返回 nilable，也不退化成 Dynamic。
- 原语在运行时构造 Option，需要 `calcit.core/Option` 定义可用。native 通过 `src/builtins/option_value.rs` 从 program 解析定义；预处理遇到这些原语时确保 `Option` 已编译；JS 在 `bind_struct_definition` 里登记 core Option。
- `Option` 的定义本身运行宏，所以宏不能调用返回 Option 的原语；`defenum`、`defstruct`、`defimpl`、`deftrait` 等宏改用 `&list:nth` 加 `&list:empty?` 保护。
- `&get-env` 删除第二个默认值参数（breaking change，0.31.0）。
- `let{}`、`select-keys`、`&get-raw` 通过显式 `match` 保持可观察的 nil 行为。

## 兼容边界

公开包装函数签名不变；直接调用原语的代码要改成 `match` / `.unwrap-or`。迁移说明在 `docs/run/upgrade.md`。

## 验证

`cargo test`、`calcit calcit/test.cirru`、`node scripts/run-core-tests.mjs`（native / js / wasm / wasi）和 `scripts/check-known-assertion.mjs` 的 env 部分。WASM `&parse-float`、`&enum:definition`、`&impl:origin` 保持 unsupported，并写入两处排除表。
