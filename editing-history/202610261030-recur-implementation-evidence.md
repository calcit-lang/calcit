# 递归循环保留实际方法证据

## 复现与选择

公开 `contains?` 的非递归调用已经保留实际名义实现，但接收者经过 `recur` helper 后仍丢失这份证据。默认普通方法可运行，自定义普通方法错误选择默认实现，默认和自定义公开函数都会在 WASM/WASI 实际执行后陷阱；同一源码的 native/JS 通过。普通检查和现有独立 callable proof 也通过，不能通过新增前端拒绝来掩盖后端问题。

复用现有 IIFE 的 loop、参数槽和 block depth 处理，在已有静态调用点特化里生成固定参数的循环体。循环携带原调用点的实际参数证据，每条回边都检查数据合同及实际 impl 表不变。保持现有 f64 ABI，不按方法名或擦除后的值猜类型。

名义数据的相容性不能替代 impl 身份；相同名义数据换成另一份 impl 必须拒绝当前特化，不能继续沿用初始证据。内层 loop 拥有独立参数槽和证据；正常结束或生成失败都恢复外层状态。原 IIFE 的保守路径及匿名方法的递归展开保护保持不变。

这不是整个公开 Enum 分派任务的结束：迭代中改变 impl、不同实现的开放分支、捕获闭包以及命名递归特化仍按现有能力边界处理；本次不宣称支持这些情形，也没有批准 ABI 扩展。

## 验证放置

- 原 trait fixture 的 definition `:tests` 增加默认/自定义方法与公开函数、长循环、同实现新 payload/变体、参数并行交换、内外 loop 遮蔽和有序副作用。通过现有 portable tag 和共享运行器回放四后端。
- impl 变化的两项源码测试保留在同一 fixture，native/JS 执行真实语义；当前 WASM/WASI 明确拒绝不成立的不变量，不加入共同能力的排除表。
- 扩展原低层 recur lowering 测试，检查相同数据合同却不同 callable 的拒绝、Number/Bool 擦除边界，以及生成失败时外层 loop 状态恢复。没有新增 Rust 测试数量；真实语言行为仍以 Calcit `:tests` 为主。
- 共享运行器只补现有输出轨迹表，固定验证两次参数求值顺序、内层调用次数和长循环结束后的一次实际 impl 执行，不新增 runner、参数或统计系统。
- 原 WASM fixture 和宿主断言补充接收者、后续参数在第二次迭代失败的场景，确认第一次回边已执行、失败后不再执行后续参数或方法。陷阱和宿主日志需要由现有 JS runner 观察，不新增 Rust 测试或并行运行器。
- Snapshot 使用官方 query、dry-run/scoped-revision 事务和完整 readback；保留原定义、附带测试、断言及 backend 排除。复跑原完整 core、WASM、Cargo、Clippy 和 check-all。
