# 准备发布 0.15.2 / Prepare release 0.15.2

## 中文

- 在升级指南新增 `0.15.2 明确宽度数值边界` 段落：说明 `Number` 运行时形状不变、refinement 只作为静态边界证明并安全拓宽、`Number` 不隐式收窄。
- 记录显式转换入口 `number->int8` … `number->float64` 返回 `Result<目标类型,String>`，拒绝非整数、符号错误、溢出、NaN/Infinity 与精度损失，不截断、不环绕、不静默舍入。
- 说明 `f64` 无法无损覆盖全部 64 位整数，只承诺可精确表示范围，host 超范围值明确拒绝。
- 记录 Component boundary 按 schema 宽度确定性导出十个独立 kind，升级需重新导出 contract 并刷新 WIT/manifest/Component，不保留旧数值 ABI；不新增顶层命令、语法或 analyzer，bindgen 不猜宽度。
- README 同步 0.15.2 的十种明确宽度数值。

## English

- Added a `0.15.2 explicit numeric boundaries` section to the upgrade guide: `Number` keeps its runtime shape, refinements are static boundary proofs that widen safely, and `Number` never narrows implicitly.
- Documented the explicit `number->int8` … `number->float64` conversions returning `Result<target,String>` and rejecting non-integral values, signedness errors, overflow, NaN/Infinity, and precision loss without truncation, wrapping, or silent rounding.
- Stated that `f64` cannot losslessly cover all 64-bit integers, so only the exactly representable range is promised and out-of-range host values are rejected.
- Recorded that the Component boundary deterministically exports ten distinct width kinds, that upgrading requires re-exporting the contract and refreshing WIT/manifest/Component artifacts with no legacy numeric ABI, and that no top-level command, syntax, or analyzer is added while bindgen never guesses widths.
- Synchronized the README with the 0.15.2 width-specific numerics.
